# 企业运营工作台 UI 设计样板

这是从 ERP 工程迁出的 **44 页本地交互设计样板**。页面、登录和文件操作使用合成数据，不连接 ERP 后端或生产账号；采购申请保留 120 条记录，默认每页 50 条。

工作台只有一个一级导航入口，个人待办、业务与团队队列、工作日历是同一页内的内容区，不再作为独立页面。

侧栏一级导航依次为：工作台、店铺信息、数据查询、运营流程、链接维护、采购处理、补货处理、出货处理、订单处理、采购档案、跨境数据、中台数据、基础配置。一级入口共用相同的样式，各使用不同的 TDesign 图标；工作台点击直达，其余分组展开子页。原“本地配置”的物品管理和系统设置归入基础配置。

侧栏使用 TDesign 原生 `Menu.collapsed` 和 `Menu.SubMenu`：宽度、子菜单和箭头动画由组件提供，折叠后通过原生浮层访问子页；主内容区按原生宽度动画的 280ms 时长同步移动。保留可聚焦按钮和隐藏子项的 `inert`，支持键盘操作；系统开启“减少动态效果”时直接切换。

账号与帮助页面通过顶部入口访问：头像菜单 → 个人资料、登录/退出登录；问号 → 帮助文档；对话图标 → 业务助手。侧栏只保留业务与配置页面。登录仍是独立的 `#login` 页面，登录成功进入工作台，退出后返回登录页；样板说明收在头像菜单中。

个人资料页参考 [TDesign Starter 个人中心](https://tdesign.tencent.com/starter/react/user/index)，采用欢迎区、个人信息网格、右侧蓝色身份卡和辅助内容的布局；手机优先展示资料。个人信息卡右上角编辑资料，身份卡右上角更换头像，保留保存、取消与未保存保护。辅助区连接现有工作台、业务助手与帮助文档；助手用量保持未接入状态，不展示虚构的访问曲线、团队成员或计量数据。

## 运行

在本目录执行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开 <http://127.0.0.1:5182/>。原书签路径 <http://127.0.0.1:5182/scripts/fixtures/purchase-request-tdesign/index.html> 也保留。端口固定为 5182，避免误连 ERP 服务。

```sh
pnpm build  # 类型检查并将两个入口与全部页面打包到 dist/
pnpm test   # 运行全部样板测试（含文件导入导出校验）
```

## 目录与边界

40 个业务及配置页面提供直接可见的导入、导出入口，窄屏自动换行。导出遵循页面当前筛选或明确勾选的范围；查询页将导出放在结果区，未查询、订单或定价零命中、条件尚未提交时禁用导出。品牌“未收录”仍是一条可导出的内部核对结果。

品牌档案、店铺归组、EAN 及评价与链接页面保留原有业务导入流程。店铺信息、每日订单发货的 XLSX 入口与其余页面的 CSV 入口共用导入样式预览弹窗：拖拽上传区、模板入口、待预检文件、通过/异常统计及逐行错误提示。可通过“样式预览”切换待上传、预检通过和存在错误状态；点击或拖放只展示示例文件，**不读取文件、不执行真实预检或导入**。弹窗内模板和确认按钮仅提示预览状态，文件限制为界面文案；店铺信息保留 XLSX 格式、10 MB 限制文案和店铺字段；每日订单发货使用原模板 16 列，Excel 示例导出不混入内部备注。原有导出及页面工具栏模板下载保留。登录、个人资料、帮助文档和业务助手不添加业务数据文件操作。

- [样板页面与合成数据](scripts/fixtures/purchase-request-tdesign/)：独立运行的 React/TDesign 源码。
- [设计交接](docs/purchase-request-tdesign-preview-design.md)、[页面覆盖矩阵](docs/remaining-tdesign-coverage.md)、[后续页面交接](docs/remaining-tdesign-design-handoff.md)：当前设计记录。
- [DESIGN.md](DESIGN.md)、[CONTEXT.md](CONTEXT.md)：迁出时复制的设计与术语参考快照；[迁移清单](migration-manifest.json)记录原文件校验值。
- `.impeccable/`：原有设计图和历史审核证据，原样归档。新的独立运行证据放在 `.impeccable/review/standalone-migration-20261019/`。

`src/lib/` 中的 CSV、工作簿和运输方式工具，以及 `src/features/middle-data/store-group-view.ts`，是从 ERP 复制的必要纯前端快照；`src/lib/types.ts` 只保留五个所需类型，工作簿下载使用本地浏览器 helper。文档中指向 `../erp/` 的链接是业务规范和正式实现的设计参照，**安装、运行、测试和构建均不依赖 ERP 目录**。本项目不含生产 API、权限或数据连接。

登录页采用 2026-10-22 确认的 [workbench 效果稿](docs/design-references/login-workbench-20261022/approved.png)：左侧约 65% 为登录区，复用 `public/workbench-mark.svg`，品牌名只展示一次；右侧为蓝灰暗色静态背景与“奇迹，从来不只在 / 它发生的瞬间。”两行文案。900px 及以下隐藏右侧区域。背景资源随项目打包，原立体背景图保留在样板自身的 `assets/` 作为历史资源，当前页面不再加载。

## Git 版本与迁移

源码仓库为 [UI](https://github.com/aying990109-source/UI)，正式业务工程仓库为 [workbench](https://github.com/aying990109-source/workbench)。

Git 保存当前源码、运行资源、测试、设计文档和依赖锁文件。`.impeccable/`、`.review/` 是本地历史设计与审核资料，不随源码上传；历史交接文档中指向这些目录的链接需要原本地归档。`node_modules/`、`dist/`、`.tmp/`、本地环境配置和日志也不提交。

界面改动按任务建立 `design/<任务名>` 分支，验证后合入 `main`。迁入 ERP 时固定采用的 UI 完整提交号，并在 ERP 的对应交接记录中注明来源文件、已采用范围和验证结果；后续只比较该提交之后的相关变化。`migration-manifest.json` 是最初迁出 ERP 时的历史清单，当前版本以 Git 提交为准。
